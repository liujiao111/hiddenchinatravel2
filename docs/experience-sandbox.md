# Experience P3 sandbox
Explicit opt-in on Preview only: STRIPE_EXPERIENCE_TEST_ENABLED=true, STRIPE_SECRET_KEY must start sk_test_, private BLOB_READ_WRITE_TOKEN and existing DRIVER_ORDER_LINK_SECRET >=32 chars. Configure a separate Stripe sandbox webhook to /api/stripe/experience-test-webhook with STRIPE_EXPERIENCE_TEST_WEBHOOK_SECRET; subscribe checkout.session.completed and checkout.session.async_payment_succeeded. Use preview deployment host, not production. Existing Resend config sends operator test notices; optionally STRIPE_EXPERIENCE_TEST_CUSTOMER_EMAIL matching the email entered in Stripe permits a test guest notice. Never send arbitrary guest test email. No live key, no live charges, no inventory claims, no real dispatch. USD1 fixed per test order, not a retail price. Test order/receipt/mail records are private and separate from drivers. Do not add purchase or conversion analytics to sandbox payment. Confirm price, inventory, operator, cancellation policy, live payment configuration and production consent separately. Test route is disabled without explicit configuration.
## P4 preview validation
- Payment status is an isolated no-store/no-referrer HTML API endpoint, not a tracked site page. Do not place order capability tokens in tracked page URLs.
- Catalog funnel view_item_list, select_item, view_item, select_experience_package, begin_checkout is wired via hct:experience-analytics-preview local event; optionally route to a dedicated NEXT_PUBLIC_EXPERIENCE_TEST_GA_ID (not the production measurement ID). No real purchase/conversion from sandbox, no PII in event payloads. Verified sandbox payment recorded privately; production GA4 purchase requires a separate approved live release.
- P4 acceptance still needs actual sandbox checkout, configured signed webhook, mail receipt, duplicate delivery, cancellation, responsive browser QA and live pricing/availability confirmation. Do not claim tests passed until observed.
